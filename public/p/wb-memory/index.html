WorkBuddy 的记忆靠谱吗？四问四答，把「忘了」这事说透。

记忆怎么工作、跨端边界、靠得住的六个硬载体，以及让复杂任务接着往下推的做法

2026-11-15

2026-11-15 与 WorkBuddy 的一次完整对话整理。 起因：好几个场景都发现它"忘了"——不同对话之间、不同电脑之间。这次专门花了一个对话，把记忆这事从头到尾问透。以下按四步问答记录，主要是我的理解，WorkBuddy 补充。

开场三条规矩

先给这次对话定规矩：回答必须查明确的资料和规定，不许靠推断；回答之前必须经过验证；每个结论都要拿出证据。事后看，这个规矩定对了——确实问出了几个不查文档根本不知道的结论。

第一问：你的记忆到底是怎么工作的？

一句话答案：WorkBuddy 的记忆 = 一份每晚更新的、有损的、按相关性召回的个人摘要档案。

它的运转是一条流水线：白天对话 → 每晚整理当天会话 → 模型自动抽取"事实信息、偏好习惯、人物关系、跟进事项"形成记忆数据 → 新对话时按"与当前请求的相关性"捞一部分注入。我可以随时在"设置 → 记忆"里翻看、修改、删除、关闭。

我的理解：腾讯确实有一套机制在处理记忆；这套机制有时间差、有滞后性（白天聊的当晚才入库）；而且说白了它是有损的，不一定靠谱——这三条官方文档自己都承认。

WorkBuddy 补充了我漏的两条，恰恰最有用：

  1. 记了 ≠ 会想起来。记忆库里有的，每次对话只按相关性捞一部分，捞多少、捞哪些，官方没公开标准。所以"忘了"有两种：没记进去，和记了没被召回。
  2. 控制权在我手里。可以看、可以改、可以当场说"记住某某"——这是主动纠偏的抓手，不是只能被动挨。

一句口诀：别把记忆当账本，把它当草稿。

第二问：不同对话、不同电脑、不同空间、不同项目，记忆是通用的还是各管各的？

一句话答案：记忆分两层——云端记忆一个账号一份到处通用；聊天记录和本地文件，一台电脑一个孤岛。

逐个场景过：

  • 换个对话聊：大方向记得，细节不记得。云端记忆所有对话通用，但上一个对话的完整聊天记录，新对话看不到。
  • 换台电脑：唯一不丢的恰恰是云端记忆（跟着账号走）；丢的是其他一切——聊天细节、本地文件、连接器授权。感觉"它不记得了"，其实不是记忆丢了，是细节丢了。
  • 换个空间、换个项目：记忆不分空间不分项目，哪儿都通用。
  • 回到老对话：全都记得，上下文百分之百完整——这是六种"记性"里最靠谱的一种，只是容量有限。

我的理解：记忆和项目、空间没有关系；记忆存在云端；召回像抽奖——挑多少、什么时间挑，跟抽奖似的。

查证中的两个收获：一是那个"记忆按账号级组织"的说法查实是另一个产品（DataBuddy）的文档，不能套用；二是官方文档没直接写"记忆跨电脑同步"这句话，这条是官方"多端协同"文档的口径（任务在各电脑本地执行、设备一对一配对）加多个独立来源交叉印证出来的，留了个实验待做：一台电脑说"记住 XX"，隔天到另一台电脑问"你记住了我什么"，一测便知。

第三问：除了记忆，还有哪些靠得住的手段？

一句话答案：六个硬载体，但本质都是文件——文件放云端就跨电脑通用，放本地就换机即失。

按管什么来分：

  • 干活的方式、规矩、底线 → 自定义指令（设置 → 个性化 → 给 WorkBuddy 的指令），一次写，处处生效。
  • 一类的活的方法论 → 专家（专家中心建自己的专家，沉淀人设加方法论，反复召唤）。
  • 事实、数据、成果文档 → 资料库（云端），存进去、对话里 @ 引用、产物存回，循环起来。
  • 正在干的活的来龙去脉 → 回原对话接着说，上下文一点不丢。
  • 周期性的动作 → 定时任务。
  • “你是谁"的偏好背景 → 记忆，只配兜底。

我的理解：这些硬规定其实就是一个个文件。文件存云端就是资料库，存自己电脑上就是工作空间；跨电脑的话本地不同步。同一个对话最准，但对话不能无限长，无限长我受不了它也受不了。

WorkBuddy 校准了一处：跨电脑不是全丢——云端那一半（资料库、专家）恰恰是跟着账号走的。文件分两种放法：放本地，换电脑就丢；放云端，换电脑照样在。资料库值得投入，就因为它是云端那一半。

第四问：那我到底该怎么做，才能让复杂任务一直往下推？

一句话答案：方法一个文件，结果一个文件，云端一放，新对话一 @，接着干。

干不完的事——一个对话装不下、一台电脑换到另一台、今天干不完明天接着来——就拆成两个文件：

  1. “怎么做的"文件：计划、步骤、方法、约定；
  2. “做到哪了"文件：半成品状态、关键结论、下一步。

放进资料库，下次新开对话就说：“WB 你先看一下咱怎么做的，再看一下输出文件在哪，接着干活。“这句话本身就是最好的接力指令。

平时就三个习惯：干完活让它把成果存回资料库；顺手更新一篇进度文档；真正想让它长期记住的，当场说一句"记住某某”。

点睛之笔：机器记不住不是病，人的记录没结构才是病

最后回到根本。其实真要把记忆做到严丝合缝，技术上不是做不到——全量存、按时间线回放、随要随调，都不难。但有一点它绕不过去：记忆还是靠人给的。我给的东西乱七八糟，它没有能力判断哪些记忆该在什么时间点拿出来，最后只会把混乱记得更牢。垃圾进，垃圾出。

所以分界线不在机器，在人：我给的东西有结构——方法归方法、结果归结果、命名清楚、放对地方——它的检索、引用、接着干的本事才能全部发挥；我给的是一团浆糊，它再聪明也只能陪我一起糊涂。

一句话收尾：我给的是垃圾，输出的就是垃圾；所以根本问题是我不能是垃圾。人的秩序是 1，机器的能力是后面的 0。

我是档案管理员，它是干活的——各归其位，就不会掉链子。
